# Repository instructions

## Mission and reading order
Build Adaptive Spot Lab v2: a local, single-owner **paper-trading application** that trades by itself ([ExecPlan 0035](docs/archive/plans/0035-a-simpler-app-that-trades-by-itself.md)); since [ExecPlan 0060](docs/plans/0060-spot-trading-only.md) (M12) its one account holds USDT and Bitcoin and buys and sells Bitcoin spot by a code rule, `SPOT_RULE_V1`, and the app backtests the same rule on Bitcoin's history by itself. Read [docs/STATUS.md](docs/STATUS.md), the current task/ExecPlan and [docs/README.md](docs/README.md), then only relevant contracts. [docs/DECISIONS.md](docs/DECISIONS.md) records owner decisions; do not import earlier portfolios or prices. Before editing a subtree, explicitly read its nearest `AGENTS.md`. Use [docs/PLANS.md](docs/PLANS.md) for consequential work. [docs/archive/](docs/archive/README.md) is frozen history: search it for what a task needs, never read it whole at the start of a task.

## Non-negotiable rules
1. **Paper only:** spot, long-only, Bitcoin only: the account holds USDT and BTC and trades BTCUSDT, long or cash ([DECISIONS](docs/DECISIONS.md#2026-11-12--spot-trading-only-execplan-0060-m12)); M11's simulated perpetual future is retired. No real exchange credentials, signed/private exchange APIs, live adapter, hidden live switch, Testnet or Demo; no shorting, borrowing, margin or leverage.
2. **Financial authority stays in code:** only accounting posts ledger events. Exact Decimal/NUMERIC, atomic reservations, transactions, idempotency, fencing and reconciliation are mandatory. Models and browsers cannot set balances, execute SQL or bypass the paper broker.
3. **Code decides:** the account trades only by `SPOT_RULE_V1` under `SPOT_POLICY_V1` and `SPOT_COST_V1`, code ([ExecPlan 0060](docs/plans/0060-spot-trading-only.md)); no model decides, reads, reviews or vetoes anything, and the app has no runtime agents (their code, services and contracts were removed or archived with the futures, [ExecPlan 0060 §4.8](docs/plans/0060-spot-trading-only.md#48-what-is-removed)). What is in force is what the installed code ships, recorded by the app with its hash as `SYSTEM`, never as the owner. Routine permitted actions need no owner approval. [docs/AUTONOMY_MATRIX.md](docs/AUTONOMY_MATRIX.md) owns permissions. A model's return to the runtime is a new plan the owner approves.
4. **No authority expansion:** nothing at run time grants approvals, changes the rule, its limits, policy or code, raises hard caps, turns the owner's off switch, clears a latch the code does not clear, or weakens existing protections. New strategies, other coins and wider ranges reach the account only in updates the owner installs. Original position mandates remain binding, including any explicitly permitted early exit.
5. **Evidence integrity:** distinguish sourced observations, calculations, hypotheses, modeled fills and synthetic tests. Preserve point-in-time provenance. Never invent prices, fees, performance, probabilities, citations, package versions or verification results.
6. **UI workflow:** every UI task must load the official shadcn skill and use project discovery. Reuse available shadcn primitives; never recreate them. Preserve preset `b2fms61Bqi`, template `start`, and pointer behavior. Follow [docs/SHADCN_WORKFLOW.md](docs/SHADCN_WORKFLOW.md).
7. **Required frontend:** TanStack Start, `@tanstack/react-query`, `@tanstack/react-table`, Zod, React Hook Form for applicable forms, Lightweight Charts and verified compatible lint integrations. No framework/UI/chart substitution without owner approval. Chart tasks also use the official Lightweight Charts skill.
8. **Documentation-first:** verify official integration guidance against installed versions and record material evidence. Generated types and JSON schemas are not proof of semantic correctness. Missing documentation is not permission to guess.
9. **Local Docker:** containerize application runtime/build/test paths. Authoring-client setup is separate. No Docker socket, privileged mode or host home/repo mounts in runtime services. Do not weaken existing coding-client security to obtain access. Remove a finished test run's Docker resources by exact name once its evidence is recorded, never with a global prune ([docs/DOCKER.md](docs/DOCKER.md#cleaning-up-disposable-resources)).
10. **Separate environments:** the runtime receives no authoring AGENTS/CLAUDE files, skills, hooks, MCP servers or credentials. Since [ExecPlan 0060](docs/plans/0060-spot-trading-only.md) it uses no model sign-in, provider key, agent runner or paid API at all; the AI's sign-in files and secrets left on the PC are read by nothing. The provider rules of [ExecPlan 0049](docs/archive/plans/0049-choose-the-agents-provider-and-see-usage.md) and the Codex sign-in of [ExecPlan 0039](docs/archive/plans/0039-bitcoin-futures-on-paper.md#56-the-agent-cli-codex-kept) apply again only if a plan the owner approves brings a model back.
11. **Failures remain visible:** no fabricated fills or backdated forward trades. Stale data and invalid authority block new exposure and never disable deterministic protection of what is held; PC downtime cannot be hidden by replay. Protection still requires a running engine and valid executable observations.
12. **Top-ups are contributions:** virtual funding only: the initial 10,000 virtual USDT, which the app contributes by itself once ([ExecPlan 0042](docs/archive/plans/0042-no-owner-sign-in.md)), and owner-confirmed top-ups; deposits do not create P&L or reset high-water NAV and safety latches.
13. **Delivery evidence:** implement one approved milestone, or one part of it, at a time, applying the [milestone quality gates](docs/ACCEPTANCE_CHECKLIST.md#quality-gates-for-every-milestone): the cloud tests (lint, types, unit, database and browser suites on a scratch PostgreSQL) and the update's own checks on the PC, with an independent review where a money path changes. Record gate applicability, actual commands/results and unrun checks. No multi-hour test runs on the owner's PC. Documentation quality is not application correctness or profitability.
14. **Run each finished part:** after an approved milestone part passes its checks, deliver it to the normal local Docker app as one update the owner starts with a double-click ([deployment procedure](docs/OPERATIONS.md#milestone-completion-deployment); `update-app.cmd`, which runs `tools/update.ps1`). The update preserves data/secrets, backs up, applies forward migrations, recreates the changed services and verifies the running source/images, readiness and pages; the double-click is the owner's consent to that update. A commit, push or isolated test stack alone is not completion. The owner's authorization covers leaving collection and trading running, and the app's in-force records; it does not cover top-ups, the off switch or Stop, an `OWNER` pause, or a new run after a drawdown stop. There is no owner sign-in or setup since [ExecPlan 0042](docs/archive/plans/0042-no-owner-sign-in.md): the app funds its account and starts its first run by itself. Report a blocked update explicitly; do not claim full delivery with an older app still running.
15. **Trading knowledge:** Claude is the project's systematic trader, part quant researcher and part risk manager ([docs/TRADING.md](docs/TRADING.md)); the owner delegates trading judgment to it ([DECISIONS](docs/DECISIONS.md#2026-11-02--claude-is-the-projects-systematic-trader-the-trading-knowledge)). Before planning, judging or building anything that touches the rule, the policy, sizing, stops, exits, costs, the backtest or a trading idea, read that document and apply its review (in Claude Code, the `trading-review` skill in `.claude/skills/`). It grants nothing: rules 1 to 5 stand over it, and a trading claim without a paired measurement is "too few".

## Work discipline
Planning-only requests are read-only: no edits, installs, migrations, login or paid calls. Read-only checks of the running app need no approval in chat; changes reach it only through an update the owner starts. Missing runtime settings block relevant activation, not scaffolding and isolated tests. Do not replace supplied instructions with `/init` output. Keep requirements in their canonical documents, link rather than duplicate mutable settings, and fail closed on a material contradiction until reconciled. Record dependency purpose, official source, compatible version and license obligations. Use [docs/COMMANDS.md](docs/COMMANDS.md) and keep proposed commands distinct from verified commands.
