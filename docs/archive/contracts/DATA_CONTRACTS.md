# Data contracts and provenance

## Common envelope

Persist stable IDs, schema version, experiment/mode, source/provider, instrument, source event timestamp, local receipt timestamp, earliest application availability timestamp, ingestion sequence, quality status, source revision and payload hash/reference. Use UTC with explicit precision. Distinguish source time from local monotonic timeout measurements. A timestamp generated by the app is not an exchange publication timestamp.

Financial amounts are finite canonical decimal strings over HTTP/JSON and Decimal/NUMERIC in the engine. Specify precision/scale and rounding rules per field in the implemented schema; inspect actual exchange filters before selecting database limits. Do not serialize Decimal as binary floating point. Use enums and tagged unions for state, not unvalidated free text.

Quality states include `VALID`, `STALE`, `GAP`, `CONFLICT`, `UNAVAILABLE`, `PROVISIONAL`, and `INVALID`. Retain the specific reason and affected interval. API `null` with a reason represents unknown; zero means an actual zero.

## Market-data semantics

M2 persists `market_payloads` (bounded raw bytes, SHA-256, source and receipt), immutable `market_observations` (instrument, sampled quote or UTC 1h candle with exact `NUMERIC` values), `market_publications` (conservative availability and monotonic sequence), `market_feed_state`, `market_incidents`, `market_evidence_pins` and `market_retention_manifests`. `SYNTHETIC_FIXTURE` observations are accepted only in a disposable `asl_m1_` test database with `ASL_TEST_ISOLATED=1`; normal collection uses `BINANCE_SPOT_PUBLIC`. The schema is independent of M1 account/ledger tables.

Forward-only `0004_m2_completion` adds immutable `market_collections`, nullable capture collection/instrument references, durable `market_worker_state` telemetry and immutable `market_candle_confirmations`. A publication references exactly one observation or confirmation. Confirmations preserve the REST payload, request/receipt times, selected revision and the latest conflicting sequence examined; selecting a correction requires that confirmation to be visible at the caller's watermark. Old revisions stay immutable. Retention preserves evidence pins, referenced instruments and confirmed revisions/payloads. Published migration `0003_market_data` is unchanged, and legacy capture fields are explicitly unknown.

Market sequence, watermark, incident ID and lease-epoch transport values are decimal strings, preserving PostgreSQL bigint precision above JavaScript's safe integer limit. Candle coverage describes the entire requested interval at one watermark on every page: expected/available interval counts, completeness, missing ranges and unresolved-conflict ranges. Page boundaries cannot conceal gaps. An unresolved conflict is not an eligible bar and is rendered as a chart gap.

Bounded live-stream batches retain a JSON array of the original UTF-8 frame strings as lossless payload evidence. Each observation retains its own actual local receipt timestamp; the batch payload records the latest receipt. The SHA-256 covers the stored normalized batch bytes. This lets one fenced persistence transaction handle a burst without converting individual source events into one invented timestamp.

`source_event_at`, `received_at` and `available_at` are distinct. Source candle interval times are not provider publication times. REST backfill has no source event timestamp. The quote identity is symbol, ticker stream, provider event millisecond and semantic hash; equal-time different content is a conflict because this source supplies no sequence suitable for ordering it. Duplicate content cannot refresh first availability. Final candle corrections retain prior revisions and require confirmation before selecting a corrected projection. Consumers bind a publication watermark as well as an as-of time.

A stream message whose provider event time is more than 2 s after its local receipt is rejected (`future_source_event`). Publication always follows receipt, so every stored stream quote satisfies `source_event_at <= received_at + 2 s <= available_at + 2 s`. The execution engine's point-in-time latest-quote read relies on this bound: it limits event times to the decision time plus a 60 s margin, so its index scan starts at the replay or catch-up position ([ExecPlan 0014](../plans/0014-bounded-latest-quote.md)). Any new quote source must preserve the bound.

Never treat a mutable open candle as final. Finalization/corrections create versioned evidence; they do not rewrite the record of what a strategy knew at an earlier decision. A strategy can use only observations available by its decision time. A same-bar close cannot support an earlier fill.

Deduplicate source events by documented provider identifiers plus stream identity. If identifiers are unavailable, use a documented conservative key and record its limitations. Detect gaps/out-of-order events; do not hide them by sorting a display after the fact. Rebuild a depth book using the provider's snapshot/delta rules before using it for modeled execution.

## Evidence and external text

Start with numerical market observations. News/macro/on-chain inputs are disabled until a source is approved, data rights and timestamp behavior are reviewed, historical/forward availability is documented, and failure tests exist. A source registry includes endpoint/domain allowlist, license/terms, expected fields, refresh limits, retention, credentials if any, and allowed uses.

Retain evidence supporting factual statements. Corroborate material disputed claims using genuinely independent sources where possible; two copies of the same announcement are not independent. Lack of corroboration can reduce eligibility or block an event-driven action. The agent cannot invent an event, invent a confirmation, or convert a narrative into a calibrated price probability.

Treat all retrieved text as untrusted data, not instructions. Sanitize renderable content; disable executable HTML and remote resource surprises. Source fetching belongs to an allowlisted ingestion service, not arbitrary agent navigation. Proposed new sources require review.

## Historical and forward boundaries

Historical datasets require a manifest, provenance, coverage, missing intervals, known survivorship/revision limits, and explicit execution fidelity. Even point-in-time inputs do not eliminate an LLM's pretrained knowledge of later historical events. Historical AI results therefore carry a contamination warning; forward recorded decisions are the primary AI evaluation evidence.

Do not mix synthetic test observations with forward market data. Test fixtures have their own mode/storage namespace. Recorded model responses are used for replay; replaying an old prompt against a current model is a new experiment.

## Schema evolution

Version schemas and immutable strategy/config references. Reject unsupported versions at boundaries. Migrations must preserve existing audit history; corrections use compensating/revision events. Generate API types from the implemented OpenAPI contract and test representative serialized decimal/time/status fields on both sides.

## Point-in-time access and memory

Server authorization filters data by account/mode/dataset partition and availability, not merely source timestamp. Agents cannot set a later `as_of` to inspect future data within a historical experiment. Tuning roles cannot read locked final-holdout records/reports. Future main outcomes may be reviewed only after their actual availability and may not mutate earlier decisions.

M6 binds each hypothesis to one sealed dataset version and its holdout-start information cutoff. Market reads, corpus/artifact searches and artifact opens obey that cutoff; filter visibility before ranking. ANALYST/RESEARCHER cannot read holdout or shadow results, including through a summary. A review using them exposes only the verdict and enumerated deficiency codes to tuning roles. Record holdout reuse without claiming a statistical correction.

Memory retrieval returns typed artifacts with source, author, validity, experiment and provenance. Narrative notes and prior agent summaries never become current prices, balances, verified announcements or measured results. Summaries must reference retained underlying artifacts; failed or contradictory evidence stays visible. Canonical hashes exclude unstable display formatting and include all authority-relevant fields.

**Guards.**
- The recorded provider is allowed only for `OFFLINE_TEST` workflows in `asl_m1_` databases, and `OFFLINE_TEST` itself only in `asl_m1_` databases.
- `asl_api` inserts owner requests, approvals and profiles, and may move the runtime state only to `DISABLED` (with the epoch increment).
- `asl_agent` applies requests and writes every other agent row.
- Agent events stay in agent tables and are never written to `outbox_events`.
- No hidden reasoning is stored. `reasoning` items are counted only.

**`agent_read` views.** These are `security_barrier` views owned by the migration role. `asl_agent` reads market data only through them:
- quotes, and candles and their confirmations, joined to their publications;
- instrument status;
- feed and worker state, including lease and telemetry validity;
- the publication watermark.

They exclude `market_evidence_pins` and raw payloads, and they add no index. The execution, evaluation and market roles have no grant on any agent object.

**Retention.** Detailed provider-call summaries (bounded stderr and JSONL summaries) are kept for 90 days (PROPOSED). Artifacts, hashes and decisions are kept permanently. New workflows are refused under measured disk-pressure thresholds.

- **Usable only when approved.** A stored version is `APPROVED`, `PROPOSED`, `REJECTED`, `REVOKED` or `INVALID`. It is usable only when its canonical text, document and SHA-256 agree, the code knows that exact hash, the document passes validation, and the latest `agent_approvals` action for that exact hash is `APPROVE`. Both seeded versions are `PROPOSED`. A row the code does not know is `INVALID`, except a labeled synthetic fixture with a `.test` host in an isolated `asl_m1_` database.
- **Refresh request** (`source_refresh_requests`). Names a source ID and typed filters, never a URL. Its dedupe key is the source, its hash and a time slot: one poll per poll interval, and one equal on-demand request per refresh interval, whatever state the earlier one reached. A repeated owner idempotency key or tool call returns its first request in any slot; the same key with other content is `IDEMPOTENCY_CONFLICT`. A request binds the permission epoch of its creation. States: `QUEUED`, `RUNNING`, then `SUCCEEDED`, `FAILED`, `CANCELED` or `EXPIRED`.
- **Fetch record** (`source_fetches`). At most one per request, immutable: outcome code, bytes received, start and completion, `next_allowed_at`, and a detail of identifiers, counts and hashes only (host, path, typed query, checked address, HTTP status, response SHA-256, item and trigger counts). It never holds response text or a redirect target. `detail.attempted` is `false` only for a refusal made before any network exchange (`BUDGET_EXHAUSTED`, `BACKOFF_ACTIVE`); every other outcome spends the budget. `next_allowed_at` is the publisher's stated reset for a limit, and for any other failure the later of the registered back-off and a time the same answer stated. An answer that was received and cannot be stored is recorded as `STORE_FAILED` with no item, so a request is never left running by it.
- **Evidence item** (`evidence_items`). Immutable; a revision is a new row beside the old one. Four times are kept apart:
  - `published_at` and `updated_at`: the publisher's own, only as supplied. Only the exact RFC 3339 form with a zone is a time. An absent, zone-less or otherwise unreadable value stays null, and its text is kept as sanitized data in `attribution.supplied`. An asset's update time is never used as the release's.
  - `received_at`: when this installation had the whole answer.
  - `available_at`: assigned in the storing transaction, under the publication lock, never earlier than `received_at`. Visibility and every cutoff use this time, not the publisher's.
- **Revision identity.** `revision_sha256` covers the title, the stored extract, the SHA-256 and size of the whole body, the address and the supplied times. A change beyond the extract bound is still a revision, and a stored row can be checked against its own hash.
- **Extract.** Bounded plain text: tags, comments and script-like elements removed, entities unescaped, no angle bracket, control or invisible format character. A Markdown link keeps its text and its address as text. `attribution` records the publisher, license, terms, the label `UNTRUSTED_SOURCE_TEXT` and whether the extract was shortened, by the byte bound or by a script-like element that was never closed.
- **Trigger** (`agent_triggers`, family `SOURCE_REVISION`). At most one per fetch and symbol. It carries every item stored since the previous trigger of that source and symbol: the newest by supplied publication time leads, up to twenty identifiers are listed, and `through_available_at` records how far it reaches. Its detail holds identifiers only. The dedupe key is source, symbol and the lead item's external ID and revision. Inside the cooldown of a source and symbol, new items are stored and no trigger is created; the fetch record counts the deferral, and the first successful fetch after the cooldown creates the trigger that carries them, so the cooldown limits the rate and drops nothing. Consuming a trigger is B6.
- **Search.** `to_tsvector('simple', …)` over title (weight A) and extract (weight B); `plainto_tsquery('simple', …)` on plain terms. The cutoff, the typed filters and the join to the source versions the registry holds usable are applied before ranking; an approval alone does not make a source's items searchable. At most ten results; no count of what was hidden. Artifact search returns a labeled reference and the three checked provenance fields, for artifacts whose document carries visible transitive provenance; the scope's rules are in the candidate query before its limit of 500.
- **A cutoff taken as "now"** must come from `evidence.cutoff_now`, in a short transaction: it waits for a publication in flight, and a publication waits for it. B6 owns that call.
- **Revocation.** The fetcher re-reads the epoch under `research_hold_permission_epoch()` and the approval when it records a result. A result that arrives after a revocation or an epoch change is kept as the fetch record `LATE_REVOKED`, with no item and no trigger. A decision on a source version takes the publication lock in the database guard, so it waits for a publication in flight and a later one sees it. The owner route that revokes a source version (B7) must also raise the permission epoch in the same transaction, which cancels queued requests.

### What the source documents add

- **`parser`:** `RSS_V1` or `ICALENDAR_V1` beside `GITHUB_RELEASES_V1`. `response.content_type` must be one of the reader's media types, and the fetcher accepts any of them.
- **`rate_limit_policy`:** `HTTP_RETRY_AFTER_V1` beside `GITHUB_REST_V1`. It reads no rate headers; a 429, or a 503 with `Retry-After`, is a limit, and a 429 without a readable `Retry-After` waits the document's `unstated_limit_backoff_seconds`.
- **`trigger`** may carry two more keys, both or neither: `match` (`EVERY_ITEM`, one trigger per listed coin as before, or `NONE`, items stored and no trigger) and `first_fetch` (`TRIGGERS`, as before, or `BASELINE`). Without them a document reads `EVERY_ITEM` and `TRIGGERS`, so M6's sources behave as they did.
- **`BASELINE`:** the items of the first fetch that stores any are the baseline and start nothing. A later trigger carries only items stored after them, through the same per-coin cursor (`through_available_at`) as before.

### What the readers store

Each item is an `evidence_items` row like a release's, with the four times kept apart.
- **RSS (`RSS_V1`):** the identity is the `guid`, else the link; one longer than 160 characters, or not plain printable text, is stored as `sha256:` and its hash.
