## Replay step throughput — 2026-09-29

[ExecPlan 0017](../plans/0017-replay-throughput.md) changes how the replay uses PostgreSQL and SQLAlchemy. No dependency was added or upgraded (PostgreSQL 17.11, SQLAlchemy 2.0.54, psycopg 3.3.6). Official sources were read on 2026-09-29.

**PostgreSQL 17.11**
- **[Asynchronous commit](https://www.postgresql.org/docs/17/wal-async-commit.html).** The risk is losing the latest transactions, never corruption or reordering; the mode can be chosen per transaction. The replay batch issues `SET LOCAL synchronous_commit = off` ([SET](https://www.postgresql.org/docs/17/sql-set.html): it lasts until the end of the transaction). A real-role test shows `off` inside a batch and `on` in any other transaction.
- **[Row lock conflicts, Table 13.3](https://www.postgresql.org/docs/17/explicit-locking.html#LOCKING-ROWS).** `FOR KEY SHARE` conflicts only with `FOR UPDATE`. A batch therefore holds the execution lease `FOR KEY SHARE` while the synchronous lease renewal still succeeds, and a real-role test renews the lease while a batch is open.
- **Planner behavior (verified by test, not from documentation).** A `max()` aggregate over the observation/publication join did not use the partial final-candle index. `ORDER BY open_ms DESC LIMIT 1` does. The `EXPLAIN (ANALYZE)` test stores 1,000 visible finals and 50 later ones. It reads at most 55 rows, and at most 5 at the live watermark.

**SQLAlchemy 2.0.54**
- **[Connection pooling](https://docs.sqlalchemy.org/en/20/core/pooling.html).** `pool_pre_ping` pings at every checkout, and reset-on-return rolls back. The baseline probe counted three checkouts per step; the fast path makes about one checkout per 150 steps.
- **[Core events](https://docs.sqlalchemy.org/en/20/core/events.html).** `before_cursor_execute`, `after_cursor_execute`, `commit` and pool `checkout` listeners are attached to an `Engine`. They are used only by the test-image probe in `tests/m3_performance.py`, never by the application.
- **Statement classification.** The application's fast path classifies statements through a thin connection wrapper that reads `TextClause.text`. It does not use an event listener.

## Research job cost and the analyst's search — 2026-10-09

[ExecPlan 0025](../plans/0025-research-job-cost-and-search.md) changes how a research job reads and writes PostgreSQL and how the engine's plain decimal operations use their context. No dependency was added or upgraded (PostgreSQL 17.11, SQLAlchemy 2.0.54, psycopg 3.3.6 with libpq 18.0.6, Python 3.13). Official sources were read on 2026-10-09; the plan's §7 holds the links and what was taken from each.

**psycopg 3.3.6**
- **[COPY](https://www.psycopg.org/psycopg3/docs/basic/copy.html).** The dataset hash reads the rows of a sealed range as the binary `COPY ... TO STDOUT` stream of the driver's own connection, in chunks of sequence numbers. The documentation gives the stream as blocks of bytes; the header and trailer are taken off by the application so that the hash is of the rows alone, however the range is cut. A driver error on that connection is not translated by SQLAlchemy, so the application raises it as the SQLAlchemy error its callers handle.
- **Not documented, held by a test:** the cursor's `rowcount` after a `COPY`. The rows a chunk sent are compared with the rows counted only when the driver reports them; a test fails if it stops doing so.
- **Parameters as arrays (rejected after measuring).** A list parameter is dumped to an array literal element by element in Python: 9.5 s of a 211 s profile for the held rows of one cell. The rows now travel as one JSON text parameter.

**PostgreSQL 17.11**
- **[COPY, binary format](https://www.postgresql.org/docs/17/sql-copy.html).** The format is not promised across major versions; a store sealed under one and read under another could be refused, which fails closed.
- **[Table functions](https://www.postgresql.org/docs/17/queries-table-expressions.html#QUERIES-TABLEFUNCTIONS) and [JSON functions](https://www.postgresql.org/docs/17/functions-json.html).** `jsonb_array_elements(...)
