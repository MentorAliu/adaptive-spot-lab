# Integration evidence register

What was verified about each library and provider the spot app uses, with its source and date. The records up to ExecPlan 0058 (M0's installed integrations, M1 to M11's, the agents' CLIs and providers, the research cluster) are in the [archived copy](archive/contracts/INTEGRATION_EVIDENCE.md); they stay the evidence for the versions they name. The resolved dependency graphs are in [pnpm-lock.yaml](../pnpm-lock.yaml) and [uv.lock](../services/engine/uv.lock); the commands in [COMMANDS](COMMANDS.md).

## Required record per material integration

| Field | Record |
|---|---|
| Integration | Libraries/frameworks involved and their responsibility boundaries |
| Versions | Actual installed versions, lockfile location, runtime and package manager |
| Sources | Official URLs, access date, relevant section, upstream skill revision where applicable |
| Observed configuration | Actual exports, signatures, generated paths and preset/base/library details |
| Implementation | Chosen pattern and alternatives rejected |
| Verification | Test names, exact commands, actual results and evidence location |
| Exceptions | Unsupported combinations, intentional deviations, unresolved risks |

Records exist for the shadcn preset and skill; Start, Router and Query SSR; shadcn with Table, RHF and Zod; Lightweight Charts with React and Start; the ESLint plugins; OpenAPI and TypeScript; the Docker and Start production build; and the engine's transactions (in the archived copy, below).

Documentation from `/latest` can change. During implementation, compare it with installed versions and official migration/source material. Do not select a moving dependency merely because its documentation was accessed today. Pin the resolved versions after compatibility checks.

## ExecPlan 0047: live trades and pop-ups — 2026-10-30

As recorded for the futures account on that day; since [ExecPlan 0060](plans/0060-spot-trading-only.md) the same code serves the spot fills (`/v1/spot/live`, the key `["spot"]`, the lock and channel `asl.spot.live`). Recorded by the project thread "Show every trade live with pop-ups" for [ExecPlan 0047](archive/plans/0047-live-trades-and-pop-ups.md) in a cloud session with no Docker. No dependency was added to the web or the engine: `git diff --stat 89954ed` over `apps/web/package.json`, the lockfile, `components.json`, `src/components/ui/`, `src/styles.css` and the engine's `pyproject.toml` and `uv.lock` is empty. No new host, source, secret or model. The official sources are the plan's [§7](archive/plans/0047-live-trades-and-pop-ups.md#7-official-sources), read at the installed versions; what the installed code does, below, was read in `node_modules` and the engine's `.venv` or seen in a test.

- **TanStack Query 5.104.0.** Each event calls `queryClient.invalidateQueries` (the `["futures"]` prefix, and for the twins a `predicate` on the key's second part); nothing calls `setQueryData`, so every number is still a read. `refetchInterval` is a function, which the installed `QueryObserver` recomputes on every query update and option change; the unit tests check each interval in each state.
- **TanStack Start 1.168.58.** The route is `createFileRoute('/api/live')({ server: { middleware: [createCsrfMiddleware()], handlers: { GET } } })`; `pnpm build` regenerated `src/routeTree.gen.ts` (no `tsr` command is installed). OBSERVED in the installed `@tanstack/start-client-core` 1.170.32 (`dist/esm/createCsrfMiddleware.js`): it checks `Sec-Fetch-Site` first (`same-origin` by default), then `Origin` against the request's origin, then `Referer`, and refuses a request with none of them unless `allowRequestsWithoutOriginCheck` is set (it is not). The built browser bundle (`.output/public`) holds none of `privateStream`, `X-Internal-Key`, `liveStream` or `api_internal_key`.
- **FastAPI 0.141.1** (`fastapi.sse`): `response_class=EventSourceResponse` with an async generator of `ServerSentEvent`. The route's dependencies run before its header is validated, so a 503 can come before a 422. OBSERVED on the wire with a real uvicorn: `data` is JSON with `json.dumps`'s default separators (`{"state": "READY", "cursor": "13"}`), the fields in the order `event`, `data`, `id`, `retry`, and the app's middleware sets `Cache-Control: private, no-store` on `/v1/futures`.
- **psycopg 3.3.6.** The listener's `AsyncConnection.connect(..., autocommit=True, keepalives=1, keepalives_idle=30, keepalives_interval=10, keepalives_count=3, application_name="asl_futures_live")` and `notifies(timeout=30)`; on the scratch cluster a `pg_terminate_backend` of that connection ended the generator with an error, and the listener closed its streams and listened again.
- **PostgreSQL** (the scratch cluster's 16.15; the app runs 17, whose `NOTIFY` page §7 quotes): a rolled-back `pg_notify` was never delivered and a committed one was, after the commit.
- **uvicorn 0.54.0.** `--timeout-graceful-shutdown 3` in the image's command. On SIGTERM with a stream open, the scratch API logged "Cancel 1 running task(s), timeout graceful shutdown exceeded"; the stream ended 3.15 s after the signal and the process exited after 4.32 s.
- **Browsers** (WHATWG HTML and MDN, §7): `EventSource`, Web Locks (`navigator.locks.request` with a `signal`, held while the callback's promise is pending), `BroadcastChannel`, the Notifications API (the permission asked on a click only, a `tag` per fill) and `document.hasFocus()`. OBSERVED in the preinstalled Chromium (build 1243): at `http://web:4318`, not a secure context, each of three tabs opened its own stream (Web Locks exist only in a secure context); at `http://localhost:4318` one stream served three tabs and another tab opened it when its tab closed.
- **Zod 4.6.5.** The stream's events and the messages between tabs are strict schemas (`liveMessageSchema`; the activity's own `activitySchema`, extended with `after`), so a tab drops anything else.
- **The shadcn skill.** Fetched at 17:21:25 UTC from `https://raw.githubusercontent.com/shadcn-ui/ui/main/skills/shadcn/`, with the same SHA-256s as 0045's (`SKILL.md` `93951e5e…3d27592`, `cli.md` `a381e35b…0838904`, `rules/composition.md` `f282df82…5af01aa41`, `rules/styling.md` `f88fbd72…01798c`, `rules/base-vs-radix.md` `2b2deb47…ed0d1ba8`, `rules/icons.md` `d4a58266…c2535`), read before the first web edit.
